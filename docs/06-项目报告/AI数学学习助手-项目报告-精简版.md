# AI 数学学习助手 · 项目报告（精简版）

> 从用户调研到 MVP 产品设计 | 2025.09–2025.11 | 个人项目 · 产品设计与 0→1 搭建
> 角色：产品经理 + 交互/视觉设计 + 全栈开发

## 一、项目一句话

面向中学生/大学生的 AI 数学学习助手，解决"解题跳步、无法按学生思路纠错"两大痛点，通过「拍照识题 → 分步讲解 → 错因分析 → 同类题」闭环，帮助学生看得懂、能纠错、会迁移。

> 口号：不跳步地讲懂，顺着你的思路纠错。

## 二、方法论与里程碑

## 三、用户调研要点

**样本**：初中/高中/大学各 5 人，成绩三档分层，一对一访谈 45–60 分钟，关键词编码归纳。

**3 类场景**：S1 作业即时答疑（100%）；S2 考前备考刷题（73%）；S3 预习自学（53%）。

**5 大痛点**：P1 解题跳步看不懂（93%）；P2 无法按思路纠错（80%）；P3 缺"为什么"（67%）；P4 讲解模板化（60%）；P5 识题不准（47%）。

**3 类用户画像**：小航·作业救急型（要快、要能看懂）；小雨·错题突破型（要纠错、要同类题）；学长·概念钻研型（要推导、要追问）。

**RICE 排序（MVP）**：

| 优先级 | 需求 |
| --- | --- |
| P0 | 分步讲解（13500）、拍照识题（9600）、错因分析（6400） |
| P1 | 答案折叠（9000）、深度三档（8000）、同类题推荐（5600） |
| P2 | 苏格拉底引导（2000）、错题本（1250） |
| P3 | 多端形态（667）、知识点图谱（500） |

## 四、竞品与 PRD 要点

**竞品结论**：Khanmigo 引导好但太慢；豆包多模态强但跳步、不纠错；Photomath 识别强但讲解机械化。三家都没做"按学生思路纠错" → 本产品第一差异化卖点。

**MVP 功能范围**：F1 拍照识题、F2 分步讲解、F3 错因分析、F4 同类题推荐、F5 答案折叠（含逐条验收标准）。

**北极星指标**："看懂率" = 看完讲解后能独立做对同类题的用户占比；护栏 = 直接复制答案率（越低越好）。

## 五、原型与 MVP

Figma 低保真/高保真 → 可交互 Demo（HTML/CSS/JS + Node，零依赖）。

- **大模型模式**：配置 LLM_API_KEY（OpenAI 兼容，如 DeepSeek），任意题目分步解析。
- **规则引擎模式**：无 Key 时离线解 7 类题型，失败自动回退，演示不中断。
- **已实现**：拍照识题、分步讲解（每步"为什么"、深度三档）、错因分析、同类题推荐（错一练三）、答案折叠。

## 六、验证与迭代要点

**10 人内测结果**：CSAT 4.2、NPS 40、讲解后同型题正确率 82%、迁移正确率提升 21%、任务闭环成功率 88%、讲解耗时 P90 4.6s 均达标；错因定位准确率 78%（目标 85%）、手写识别 66%（目标 70%）未达标。

**V1.1 优先级**：P0 = 错因步骤对齐 + 错因标签扩展、手写识别优化；P1 = 答案二次确认、步骤追问、苏格拉底引导；P2 = 错题本。

**结论**：核心假设得到验证，差异化（错因分析）被用户认可；短板明确，迭代路径清晰。

## 七、运行方式

双击 `prototype/start.command`，或 `cd prototype && node server.js` 后访问 http://localhost:8080；在 `prototype/.env` 配置 LLM_API_KEY 即可接入真实大模型。
