# 01 用户调研：调研方案与结论

## 一、调研目标

1. 摸清中学生/大学生学习数学时的**核心使用场景**；
2. 识别使用 AI 数学工具时的**高频痛点**（尤其是"解题跳步、无法按学生思路纠错"）；
3. 为需求优先级（RICE 打分）和 PRD 提供**一手证据**。

## 三、核心结论

### 3.1 三类核心使用场景（按提及频率排序）

| 场景 | 提及率 | 典型情境 | 核心诉求 |
| --- | --- | --- | --- |
| **S1 作业/练习遇阻（即时答疑）** | 15/15 (100%) | 晚上写作业卡壳，需要"立刻会做这道题" | 快、能看懂、不打断思路 |
| **S2 考前备考（集中刷题+错题）** | 11/15 (73%) | 月考/期末前集中复习，反复做错同类型题 | 错因归类、同类题推荐、错题回顾 |
| **S3 预习/自学新课（概念理解）** | 8/15 (53%) | 课前预习看不懂新概念，或自学拓展内容 | 讲清概念来源、"为什么"，不只给结论 |

> 补充：大学生（U11–U15）中 S3 占比更高（4/5），且对"推导过程严谨性"更敏感。

### 3.2 五项高频痛点（按访谈提及频次排序）

| 痛点 | 提及率 | 典型原话（脱敏） |
| --- | --- | --- |
| **P1 解题跳步，过程看不懂** | 14/15 (93%) | "它直接给我 x=3，中间那几步全没了，我还是不知道 3 怎么来的。"（U06） |
| **P2 只给标准答案，无法按我的思路纠错** | 12/15 (80%) | "我按我自己的方法写，写到一半错了，它不告诉我哪里错了，只把标准答案贴出来。"（U07） |
| **P3 缺乏"为什么"，只讲"怎么做"** | 10/15 (67%) | "讲了步骤，但没讲为什么要这么变形，换个题我又不会。"（U02） |
| **P4 讲解过于模板化，无法适配个人水平** | 9/15 (60%) | "讲得太深我听不懂，太浅又浪费时间，不能选难度。"（U09） |
| **P5 识题不准 / 拍照对复杂式子识别差** | 7/15 (47%) | "手写体、分数、根号经常识别错，抄都抄不对。"（U12） |

**一句话总结**：用户要的不是"答案"，而是**"看得懂的过程 + 针对自己思路的纠错 + 可调节的讲解深度"**。

### 3.3 其他关键洞察

- **付费意愿**：11/15 愿意为"讲得明白、能按思路纠错"的工具付费，接受价位集中在 10–30 元/月；前提是"真能提分/真能听懂"。
- **对苏格拉底式引导的态度**：初中生更希望"直接讲清楚"，高中生/大学生更接受"引导式提问"（8/15 希望有"提示我下一步"的模式）。
- **对 AI 的担忧**：怕形成依赖（12/15）、怕讲解错误（9/15）、怕被老师判定抄袭（6/15）→ 需要"只看思路/答案可隐藏"的合规设计。
- **形态偏好**：网页/小程序 > 独立 App > 浏览器插件；拍照入口是刚需（13/15 提到）。

## 四、调研对后续工作的输入

| 调研结论 | 落点到 PRD |
| --- | --- |
| P1 跳步 → | 功能 F1「分步讲解」，强制展开完整步骤，每步可点开"为什么" |
| P2 不纠错 → | 功能 F2「错因分析」：学生上传自己的过程/答案，定位错因 + 纠正 + 同类题 |
| P3 缺"为什么" → | 讲解默认开启"这一步的数学原理" |
| P4 水平不适配 → | 讲解深度三档（基础/标准/进阶）+ 苏格拉底提示模式 |
| P5 识题不准 → | 拍照识题后"可编辑文本"，并支持 LaTeX 校对 |
| 依赖/抄袭担忧 → | 「先想再看」「答案可折叠」的防依赖设计 |
